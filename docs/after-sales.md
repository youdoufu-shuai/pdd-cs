# 商品咨询与售后协商：完整处理方案

> 这份方案解决两个最容易出问题的场景：
> **1）客户问具体商品参数**；**2）客户要求退款/退货/换货/赔偿等售后协商**。
> 核心原则：**机器人负责“接住、收集、解释、转人工”，不替人工做决定、不承诺结果。**

---

## 一、角色分工：AI 做什么，人工做什么

| 环节 | 智能客服（AI） | 人工客服 |
| --- | --- | --- |
| 商品参数 | 只回答知识库/详情页能确认的客观信息（材质、尺码表、规格、使用方式） | 需要判断“买哪个/适不适合”、参数拿不准、兼容性/专业问题时接手 |
| 售后受理 | 安抚情绪、收集订单号后四位/问题描述/照片、说明平台流程、立即转人工 | 核实订单和证据，决定退款/退货/换货/赔偿方案 |
| 协商/赔付/投诉 | **不承诺结果、不承诺金额、不承诺时间**，只转人工 | 按平台规则和店铺政策处理、留痕 |
| 安全类问题 | 立即转人工并停止自动回复 | 第一时间处理（过敏、受伤、漏电、食品安全等） |

> 平台规则边界：售后结果由平台判定，商家/客服不能替平台承诺“肯定能退”“包退”“赔多少”。

---

## 二、商品咨询处理流程

1. **识别商品**：客户是否发了商品卡片/订单/商品名/货号。
2. **查资料**：优先查「商品资料库」（`config/knowledge/product-catalog.md`）；
   高频商品也可以在 `config/rules/goods.yaml` 配置按商品 ID 的固定回复。
3. **能答就答**：只答客观参数；价格/库存/生产日期不写死，统一“以商品详情页/订单页面为准”。
4. **信息不足**：只问一个最关键的问题（商品名/货号/尺码/型号），不要连珠炮式提问。
5. **拿不准就转人工**：
   - “买哪个/适不适合我/推荐一下”属于判断；
   - 兼容性、专业参数、医疗/安全类问题；
   - 客户发的商品图无法对应到具体商品；
   - 知识库没有依据。
6. **禁止编造**：不虚构材质、尺寸、库存、发货时效、优惠；不评价同行。

### 商品咨询标准口径

- 尺码：按详情页尺码表对照身高体重选择；卡在两个码之间 → 转人工确认。
- 材质/成分：以商品详情页参数为准；敏感体质建议谨慎，出现过敏 → 转人工。
- 库存/补货：以商品页面显示为准，页面可拍即有货；不承诺补货时间。
- 色差：图片受光线/显示器影响，颜色以实物为准。
- 发货：发货时效以商品详情页公示为准；物流以订单页面为准。
- 保修/售后：以商品详情页和平台售后页面为准。

## 三、售后协商处理流程（标准 5 步）

1. **先安抚**：客户着急时先说“您别着急，我帮您处理”，不辩解、不反问。
2. **收集信息**：订单号后四位、商品名称、具体问题、照片/视频；一次只问一个关键信息。
3. **说明流程**：售后申请以平台页面为准（申请 → 寄回 → 商家验收 → 平台退款），不承诺结果。
4. **立即转人工**：退款/退货/换货/仅退款/赔偿/补偿/投诉/安全类问题一律转人工。
5. **人工接手**：人工核实订单和凭证后再给方案；机器人不替人工拍板。

### 分类处理矩阵

| 客户诉求 | 机器人可以做什么 | 绝对不能承诺 | 必须收集 | 后续动作 |
| --- | --- | --- | --- | --- |
| 退款/仅退款 | 说明平台售后流程、如何提交申请 | 肯定能退、包退、具体到账时间 | 订单号后四位、商品、原因 | 转人工核实 |
| 退货/换货 | 说明退货退款流程、提醒不影响二次销售 | 肯定能退、运费谁承担 | 订单号、商品、照片、是否已申请 | 转人工核实 |
| 质量问题/破损/少发/错发/假货 | 要求提供商品照片、外包装、面单 | 直接认责、承诺补发/赔偿 | 订单号、照片视频、问题描述 | 转人工核实仓库/快递 |
| 物流不更新/未收到 | 引导查订单页物流、说明可能延迟 | 已经发了、明天到、保证拦截 | 订单号、物流单号、收货信息 | 转人工联系快递 |
| 改地址/发票/备注 | 说明订单页操作方式；发票收集抬头税号 | 一定改成功、一定开出来 | 订单号、新地址/开票信息 | 转人工处理 |
| 赔偿/补偿/价保 | 只记录诉求、安抚 | 赔多少、一定补偿、退款金额 | 订单号、诉求、凭证 | 转人工协商 |
| 投诉/差评/12315/媒体 | 先安抚、不争辩 | 评价平台/同行、承诺处理结果 | 订单号、诉求、经过 | 立即转负责人 |
| 过敏/受伤/漏电/起火/食品安全 | 立即停止自动回复 | 任何责任/赔偿承诺 | 订单号、照片、就医/安全情况 | 立即转人工并留证 |

### 售后绝对不能说的话

- “肯定能退”“包退”“我帮你申请仅退款”“我说了算”
- “今天一定发”“明天到”“保证拦截成功”
- “赔你 XX 元”“我们全责”
- “加微信/QQ 私下处理”“发银行卡/验证码给我”
- 评价平台、评价同行、使用“最/第一/100%/保证”等绝对化表述

## 四、在系统里怎么落地（小白照着做）

### 第 1 步：生成标准模板（面板里点一下）

面板 **「话术与知识库 → 店铺知识库」** → 点 **「生成商品/售后模板」**：

- `product-catalog.md`：商品资料库（按真实商品填写，一个商品一段）；
- `after-sales-playbook.md`：售后处理手册（按店铺真实政策填写）。

模板里的 **【】占位内容必须替换**：价格、尺码、材质、发货时效、退换货政策、运费险等，
必须与商品详情页和店铺公告一致。

### 第 2 步：配置转人工与风控（已有默认，按需调整）

- `config/rules/transfer.yaml`：退款/退货/售后/质量/投诉/安全/价格谈判等关键词；
- `config/config.yaml → compliance.human_handoff`：
  - `notify_message`：转人工提示语；
  - `assign_cs_name`：指定售后客服；
  - `fallback_to_manual: true`：转接失败时暂停自动回复，避免乱答。
- `config/rules/goods.yaml`：高频商品的固定回复（按商品 ID），优先级高于 AI。

### 第 3 步：让 AI 也遵守商品/售后口径

面板 **「话术与知识库 → AI 客服风格 → 一键适配」**：生成的人设已经包含
「商品与售后处理」段：商品参数不编造、售后先收集再转人工、不承诺结果、安全类立即转人工。

### 第 4 步：开启 AI（可选）

面板 **「系统设置 → AI 回复设置」** 填 API Key / 模型。AI 未启用时，
商品/售后仍会走关键词、转人工和默认回复，只是不会生成自然语言回答。

### 第 5 步：上线前用测试台验证

面板「决策测试台」或命令：

```bash
python -m pdd_cs simulate "这款有175的吗" "我要退款" "质量有问题" "什么时候发货" "能便宜点吗"
```

期望：

- 商品参数类：命中知识库/关键词，正常回答；
- 退款/质量/投诉/价格：`action=transfer`，转人工原因正确，不发送承诺内容；
- 没有依据：追问一个问题或转人工，不编造。

## 五、人工交接与质检

- 工作台「待处理队列」查看转人工、转接失败、人工接管中的会话；
- SLA：首响 180 秒红线，面板/日志会显示超时；
- 告警：转人工失败、掉线、登录过期推送到群；
- 会话质检：检查未回复、重复话术、客户情绪升级、转人工失败；
- 每天复盘「转人工原因 TOP」：商品/尺码/物流/售后/价格，反哺知识库和商品资料。

---

## 六、边界与合规

- 智能客服不冒充人工；客户问“是不是机器人”如实说明，可转人工。
- 不引导站外交易、不索要敏感信息、不承诺平台规则之外的结果。
- 售后结果以平台判定为准；商家客服只解释流程和协助提交材料。
- 商品资料中的价格/库存/生产日期等易变信息，写成“以页面为准”，不写死。
- 涉及人身安全、监管投诉、法律风险的，立即转人工并保留证据。
